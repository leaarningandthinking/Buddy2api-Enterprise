# Buddy2api v2.1.7

发布日期：2026-09-13

小版本：修好一键读取供应模型（尤其是 TraeWork 仍读旧目录），并把别名、账号导入和 Windows 启动顺一下。

## 一键读取供应模型

- TraeWork 在线读取补上 `functions=solo_work_remote`，不再默认落到旧的 `solo_coder` 目录。本机实测可入库 `glm-5.3`、`kimi-k3`、`qwen3.8-max`。
- WorkBuddy 列表直接用刷新响应更新，避免第二次请求失败却提示成功。
- 提示区分「在线读取」和「回退本地」。四通道模型表统一为「模型 ID / 名称 / 操作」，ID 带通道前缀。
- 四通道官方目录都只读，不再单独编辑 WorkBuddy。自定义一律走「添加模型」，手动项在一键读取后保留。
- 对应 [#56](https://github.com/wicm84266964/Buddy2api/issues/56)。

## 按通道别名

- 别名按通道保存，只对绑定该通道的 API Key 生效，不再全局共用 WorkBuddy 映射。
- 旧的扁平 `model_aliases` 自动当成 WorkBuddy 自定义别名。内置别名不可覆盖。

## 账号导入与启动

- 「一键导入全部通道」走各启用通道默认目录；「导入当前通道」才用自定义路径。切换通道会清空路径。
- 管理页默认打开账号管理。
- Windows `start.bat` 只用 `conda.exe`，变量改为 `BUDDY_CONDA_EXE`，避免 Conda 环境下脚本直接退出。已有实例运行时打开已有实例。

## 升级说明

- 无数据库迁移。别名写入 settings，刷新结果仍写在通道目录里。
- Docker 用户需要重新构建镜像并重启服务。
- 思考强度策略未改。

## 验证

- 完整测试集：`282 passed`。
- 本机已验收：一键读取 WorkBuddy / TraeWork live 目录；四通道只读目录加手动 extras；按通道别名；账号导入拆分全部/当前通道。
