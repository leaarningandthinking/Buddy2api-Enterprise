# Buddy2api v2.1.11

发布日期：2026-09-18

小版本：把 WorkBuddy 目录里的思考档位转给 `/v1/models`，并把 WorkBuddy 失败日志按原因分类，方便回溯。跳过 2.1.10 版本号，因为该 tag 已被占用。

## 思考档位发现

- WorkBuddy 一键读取会留下上游的 `reasoning.supportedEfforts`、默认档和 `supportsReasoning`。
- `GET /v1/models` 带上这些字段；裸 id 和 `workbuddy/` 前缀都有。
- 上游没给列表就不编档。QClaw、QwenWork、TraeWork 不发明档位。
- 部署后需要再点一次 WorkBuddy 一键读取，旧目录没有这些字段。

## 失败分类

- 请求日志 `finish_reason` 区分为 `upstream_http`、`upstream_disconnect`、`incomplete_stream`、`parse_error`。
- `error_msg` 带 `[类别]` 前缀；空 HTTP 正文会写成 `upstream HTTP 502, empty body`；httpx 无文案时保留异常类型名。
- 智能体 SSE 的 `error.code` 使用上述类别。对外仍可能是 502。
- 换号再试仍记 `retry`，正文里带类别前缀。

## 2.1.9 之后已合入 main 的内容

- 各通道目录容量写入 `/v1/models` 的 `context_window` / `max_output_tokens`。
- 非流式聚合不再把缺少 `[DONE]` 或 `finish_reason` 的上游流当成成功。

## 升级说明

- 无数据库迁移。
- Docker 用户需要重新构建镜像并重启服务。
- 思考强度请求映射未改；本版只披露目录档位，并给失败日志分类。
